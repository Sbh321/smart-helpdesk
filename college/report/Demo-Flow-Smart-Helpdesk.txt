SMART HELPDESK - DEMO FLOW (after the presentation)
====================================================

Length: about 12-15 minutes. Two presenters: one drives the browser, the other speaks.
Order: website -> sign-up -> tickets, SLA, settings, reports -> platform admin.

Everything runs on the laptop (the Docker stack), so the demo does not depend on the
internet. The live site (https://shp.subhambhandari.com.np) can be opened at the very end
to show that the same system is deployed on AWS.


BEFORE THE DEMO (do this 10 minutes before)
-------------------------------------------

1. Start the stack and load the demo data:
       just up demo
       just demo-reset          (about 40 seconds; rebuilds the "acme" and "globex" workspaces)
   Run demo-reset again after every rehearsal: a rehearsal creates tickets and moves the clock.

2. Open these tabs / browser profiles, each already signed in (demo password: password):
   - Tab A  Website          https://shp.localhost                          (no sign-in)
   - Tab B  Private window   for the sign-up                                (no sign-in)
   - Tab C  Mailpit          https://mail.shp.localhost                     (all emails land here)
   - Tab D  Arjun  (Agent)   https://app.shp.localhost/acme   arjun@acme.test
   - Tab E  Priya  (Manager) https://app.shp.localhost/acme   priya@acme.test
   - Tab F  Meera  (Owner)   https://app.shp.localhost/acme   meera@acme.test
   - Tab G  Sam (other company) https://app.shp.localhost/globex   sam@globex.test
   - Tab H  Platform admin   https://admin.shp.localhost/platform   admin@platform.test

3. A terminal open in the project folder (for "just demo-tick 30" in step 4).

4. Browser zoom 125 %, light theme.

5. Pick a new workspace name for the sign-up that has not been used on this laptop
   (for example "Himal Support" -> address "himal-support"). demo-reset does not remove
   workspaces created by sign-up, so a name used in a rehearsal will show "taken".


STEP 1 - THE WEBSITE: WHAT THE PRODUCT IS  (about 1.5 min)
----------------------------------------------------------
Tab A: https://shp.localhost

Show: scroll the landing page slowly (hero, how it works, features, FAQ).

Say:
- "Smart Helpdesk is a support ticket system offered as a service. One installation serves
  many companies. Each company gets its own workspace with its own agents, customers,
  tickets and settings, and never sees another company's data."
- "This is called multi-tenancy. The workspace of every request comes from the signed-in
  user, never from the web address, and the database itself filters every query by
  workspace (row-level security)."
- "What makes it 'smart' is that it takes four decisions automatically and explains each
  one: priority, which agent, possible duplicates, and SLA risk."

Then click "Start a free trial" (in the private window, Tab B, so it opens signed out).

email address (support+himal-support@...) with a Copy button.
Say: "Customers email this address, or the company forwards its old support mailbox to it, and

Tab C (Mailpit): the welcome email has arrived too: sign-in link, the support address, first steps.
Back in Tab B: "Sign in to Himal Support" -> sign in.
The dashboard opens with the "Get started" panel: the support address again, and the setup steps
(invite the team, agents and skills, categories, SLA and business hours, logo, API and webhooks).

Say:
- "Nothing is created until the email is confirmed. The new workspace starts on a free
  trial and comes with default roles, categories, an SLA policy and a business calendar."

  30 days of realistic data: Acme Support."
  (Meera, Acme's owner, sees the same Get started panel; hide it with the X before step 3 so the

------------------------------------------------------
Tab D (Arjun), #1121: set the status to Pending -> the resolution timer shows "paused".

paused time." Then set it back to In progress.

Tab E (Priya): open #1104 "Cannot add new team members" (P1, warning, due soon).
Terminal:  just demo-tick 30      (moves the clock 30 minutes forward)

Say: "A scheduler checks the timers every minute: first a warning, then a breach, and each

IF SOMETHING GOES WRONG
-----------------------
- A page is slow or blank: refresh; the app falls back to refreshing every 30 seconds.
- Sign-up says the address is taken: use another workspace name.
- Numbers in steps 3-4 differ (e.g. not #1121, no breach): demo-reset was not run after the
  last rehearsal; skip to the next step and mention it.
- The API documentation page needs the internet; if offline, skip it.
- Laptop problem: use the screenshots in the report appendix.


QUESTIONS THE PANEL MAY ASK (short answers)
-------------------------------------------
- Why rule-based algorithms and not machine learning? A new installation has no labelled
  history, and every decision must be explained; the algorithms sit behind interfaces so a
  stronger one can replace them later.
- How is one company's data kept from another? The workspace comes from the session, every
  table has the workspace id, and PostgreSQL row-level security filters every query.
- What happens when no agent is eligible? The ticket stays unassigned and managers are notified.
- Does a duplicate get deleted? No; the agent decides. A confirmed duplicate is closed and
  linked to the original.
- How is it deployed? Docker Compose on one AWS virtual machine, set up with OpenTofu and
  Ansible, with HTTPS from Caddy.
