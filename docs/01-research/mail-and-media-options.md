# Mail server and media library options

Researched 2026-09-17 (second pass, after the owner asked for a bundled mail server and a feature-rich media library). Decisions: [ADR-0018](../adr/0018-mail-server.md), [ADR-0019](../adr/0019-media-library.md).

## Mail server (self-hosted, in the Compose stack)

Needs: outbound transactional mail with DKIM/SPF/DMARC from any VM; a relay ("smart host") option because many cloud VPS block port 25; inbound mail so replies and new emails become comments/tickets; multi-tenant sender identities.

| Option | Version (verified) | Licence | Finding | Verdict |
|---|---|---|---|---|
| **Stalwart Mail Server** | 0.16.22 (2026-09-13), weekly releases | AGPL-3.0 / Stalwart Enterprise License v2 (dual) | Single Rust binary: SMTP, IMAP4, POP3, JMAP, CalDAV/CardDAV; DKIM (v1/v2), SPF, DMARC, ARC, DANE, MTA-STS; Sieve; MTA hooks and milter for inbound filtering; webhooks for events; web admin. Configurable smart-host relay. Runs comfortably in < 512 MB. | **Chosen** (bundled, profile `mail`) |
| docker-mailserver | 14.0.0 (2026-06-29, Debian 13, Dovecot 2.4) | MIT (config) over Postfix/Dovecot | Mature, well documented; heavier (Postfix, Dovecot, Rspamd, ClamAV optional); no JMAP; configuration through env and setup script. | Alternative for operators who standardise on Postfix |
| Postal | 3.3.7 (2026-06-03) | MIT | Transactional MTA with HTTP API and inbound webhooks; needs MariaDB and a Rails runtime; designed for sending platforms rather than mailboxes. | Rejected (extra database, heavier) |
| Mailu / Mailcow | — | — | Full groupware suites with many containers. | Rejected (too heavy for a customer's Compose file) |
| External provider only (Postmark/SES/Resend + inbound webhooks) | — | — | Simplest for SaaS, impossible for air-gapped on-prem; kept as the **relay** option and as the cloud alternative. | Supported through configuration |

Inbound processing in Laravel:

| Option | Version | Finding | Verdict |
|---|---|---|---|
| IMAP polling with `webklex/laravel-imap` | 6.2.0 (2025-04-25); PHP ≥ 8.0, any Laravel | Fetches from the mail server's `inbound` mailbox; simple, debuggable; last release 17 months ago but stable and widely used. | **MVP**: `mail:fetch-inbound` every minute |
| Stalwart MTA hooks (HTTP JSON at DATA stage) | 0.16 | Pushes each message to an HTTP endpoint synchronously during SMTP; no polling delay; ties the mail server to app availability. | V1 (or when latency matters) |
| Provider inbound webhooks (Postmark/SES) | — | Cloud-only. | Supported as an alternative driver |
| Reply/quote stripping: `willdurand/email-reply-parser` | 2.10.0 (2022-01-30) | Stable but unmaintained; the heuristics (quoted lines, "On … wrote:", signature markers) are small. | We implement our own `ReplyParser` (`Automation/Domain/Text`, about 120 lines, tested against a fixture corpus); the package is not installed |
| DKIM signing in PHP (Symfony Mailer DKIM signer) | Symfony 7 | Possible, but signing at the mail server keeps keys in one place and covers relayed mail. | Not used; Stalwart signs |

DNS per sending domain: MX (inbound), SPF (`v=spf1 mx include:<relay> -all`), DKIM selector TXT (key generated by Stalwart), DMARC (`p=quarantine` after warm-up), PTR on the VM IP, MTA-STS optional. Tenants either use `support@<platform-domain>` with a per-tenant local part, or verify their own domain (V1) by adding the records shown in the UI.

## Media library

Needs: tenant file library with folders, tags, search, metadata, image thumbnails/variants, reuse across tickets and branding, quota; must fit the existing presigned direct-to-S3 upload design ([storage.md](../03-architecture/storage.md)).

| Option | Version (verified) | Finding | Verdict |
|---|---|---|---|
| spatie/laravel-medialibrary | 11.23.8 (2026-09-14); Laravel 10–13, PHP ≥ 8.2 | Polymorphic `media` table, conversions on queue, responsive images, custom path generators (tenant prefix possible), S3 support. Its ingest model is server-side (`addMedia`, `addMediaFromDisk`), so presigned direct uploads would have to be copied into its own paths, and it would duplicate our `ticket_attachments` model. | Rejected for the MVP (revisit in V1 for responsive images) |
| intervention/image | 4.3.2 (2026-08-29); PHP ≥ 8.3; GD or Imagick drivers | Resize/crop/encode for thumbnails and web variants; small and maintained. | **Chosen** for variants in a queued job |
| Own model | — | One `media_items` table replaces `ticket_attachments`; polymorphic `mediables`; folders, tags, variants JSON; quota counters; the presigned intent/complete flow already designed. | **Chosen** |
