# Host configuration (Ansible)

Terraform provisions, **Ansible configures**, Docker packages. The same playbooks configure a customer's on-prem server and the cloud VM; the inventory differs. ansible-core 2.21 with `community.docker` 5.3 (`docker_compose_v2`, `docker_compose_v2_run`, `docker_compose_v2_exec`), `ansible.posix` 2.2, `community.general` 13.4 and the `geerlingguy.docker` 8.0.0 role ([versions.md](../01-research/versions.md)). Time budget: **≤ 1.5 days** in milestone 3. This page describes the code as built in M3-14.

## Layout

```text
infra/ansible/
├── ansible.cfg                 # inventory default, roles_path roles:galaxy_roles, collections_path ./collections, pipelining
├── requirements.yml            # collections + geerlingguy.docker (pinned); installed into collections/ and galaxy_roles/ (gitignored)
├── .ansible-lint-ignore        # the unprefixed inventory-facing defaults (see below)
├── inventory/
│   ├── onprem.ini.example      # single-tenant on-prem (single host layout, tls internal)
│   ├── cloud.ini.example       # multi-tenant SaaS on any VM (split layout, tls acme)
│   ├── reference.ini           # generated by OpenTofu envs/reference (gitignored)
│   └── existing.ini            # generated by OpenTofu envs/existing (gitignored)
├── group_vars/all/vault.yml.example   # shared secrets that must live in git, encrypted with ansible-vault (none needed by default)
├── host_vars/                  # <host>.secrets.yml generated on the first run (0600, gitignored)
├── site.yml                    # full install: helpdesk_defaults → common → docker → firewall → proxy → app → backup
├── deploy.yml                  # upgrade to app_version
├── backup.yml                  # backup now (optionally fetch to the controller)
├── restore.yml                 # restore a dump (+ object archive)
└── roles/
    ├── helpdesk_defaults/      # defaults/main.yml only: every setting and its default
    ├── common/  docker/  firewall/  proxy/
    ├── app/                    # tasks/{main,secrets,images,provision}.yml, templates/env.j2
    └── backup/                 # installs infra/scripts/helpdesk-{backup,restore}.sh and the systemd timer
```

**Why a `helpdesk_defaults` role instead of `group_vars/all.yml`.** Variables in a playbook-adjacent `group_vars/all` outrank the inventory file's `[helpdesk:vars]`, so an operator's `platform_domain=…` in the inventory would be silently ignored (found in the first rehearsal). Role defaults are the only level below the inventory; every play lists `helpdesk_defaults` first, and the inventory or `-e` always wins. ansible-lint's role-prefix rule is suppressed for that one file.

## Roles

| Role | Tasks |
|---|---|
| `common` | apt base packages, time zone, unattended upgrades, `deploy` user with passwordless sudo and optional authorised key, `sshd_config.d/10-smart-helpdesk.conf` (key-only, no root; validated with `sshd -t`), swap file, `vm.overcommit_memory=1` for Valkey |
| `docker` | `geerlingguy.docker` (Docker CE + Compose plugin, `deploy` in the `docker` group, `daemon.json` with json-file 10 MB × 3); asserts Compose ≥ 2.24 |
| `firewall` | ufw: SSH `limit` from `ssh_cidrs`, 80/tcp, 443/tcp, 443/udp, default deny, enable |
| `proxy` | validates `tls_mode`/`host_layout`; copies the customer certificate to `certs/` for `tls_mode=files`. The Caddyfile itself is baked into the proxy image and switched by `TLS_MODE`/`HOST_LAYOUT` in `.env` (production.md §TLS options), so nothing is templated on the host |
| `app` | creates the tree; copies `compose.yaml`, `infra/compose/{prod,tools}.yaml`, `infra/postgres/*`, `smoke.sh`; secrets (below); images (registry pull or archive load); monitor basic-auth hash (once, with `caddy hash-password` from the proxy image); `.env` from `templates/env.j2` (0600); starts `postgres`, `valkey` (+ `rustfs`); `docker compose run migrate` (owner role); first-run provisioning (below); starts every service with `wait`; `storage:ensure-bucket` when `--check` reports a missing bucket or stale CORS; runs `smoke.sh` through `127.0.0.1:<https_port>` (5 retries) |
| `backup` | `/usr/local/bin/helpdesk-backup` and `helpdesk-restore`, `helpdesk-backup.service` + `.timer` (daily 02:30 UTC, `Persistent=true`) |

### Secrets (idempotent, per host)

`roles/app/tasks/secrets.yml` loads `host_vars/<host>.secrets.yml` next to the inventory if it exists, generates whatever is missing with `community.general.random_string`, and writes the file back (0600, controller only):

`db_superuser_password`, `db_owner_password`, `db_app_password`, `db_backup_password`, `valkey_password`, `health_token`, `s3_key`, `s3_secret` (RustFS root keys), `app_key` (`base64:` + 32 random bytes), `monitor_password` and its bcrypt `monitor_password_hash`, `platform_admin_password`, `reverb_app_key` and `reverb_app_secret` (M3-16; generated on the next run for an existing host, used only when `realtime_profile` is true; the key is public because the SPA sends it).

On the host, the four database passwords become Compose file secrets in `secrets/` (owner uid 33 = `www-data` in the backend image, group `deploy`, 0640; PostgreSQL reads them as root through `infra/postgres/entrypoint.sh`). The Passport signing key pair is generated on the host once (`openssl genrsa 4096`, same ownership) and mounted read-only into the backend containers; it is not in the secrets file, and losing it only forces API clients to request new tokens. The secrets file is the only copy of the passwords outside the host: keep it in the operator's password manager, never in git. Losing it matters most for `app_key`: a rebuilt host with a new key cannot decrypt the encrypted columns of a restored dump (webhook and API client secrets). Database passwords are recreated from the file on a fresh volume, so a dump restores under either set.

### First-run provisioning

Guarded by marker files in `/opt/smart-helpdesk` (a re-run skips them): `.seeded` after `db:seed` (permission catalogue and default roles), `.tenant-created` after `platform:create-tenant <single_tenant> "<name>" --owner=<email>` (the file keeps the command output, including the owner's invitation link, 0600 root), `.admin-created` after `platform:create-admin` with the generated password. All three run in the one-shot `migrate` container, i.e. on the owner connection. The demo data set (`DemoSeeder`) is not part of a production install.

## Playbooks

| Playbook | What it does |
|---|---|
| `site.yml` | first install and convergence; safe to re-run (second run: `changed=0`) |
| `deploy.yml -e app_version=<tag>` | `helpdesk-backup pre-deploy` → copy the release's Compose files and scripts → pull or load images → point `APP_VERSION`/`BACKEND_IMAGE`/`PROXY_IMAGE` in `.env` at the release → `artisan down` → `run migrate` → `horizon:terminate` → `up -d --wait --remove-orphans` → `artisan up` → smoke |
| `backup.yml [-e fetch_backup=true]` | `helpdesk-backup manual`; with `fetch_backup` copies the dump and object archive to `infra/ansible/backups/<host>/` on the controller (gitignored) |
| `restore.yml -e dump_file=… [-e objects_file=…] [-e upload=true]` | `helpdesk-restore` (stop app containers → drop and recreate the database from the dump as the `postgres` superuser → restore objects → `run migrate` → `cache:clear` → `up --wait`) → smoke. `upload=true` copies both files from the controller first |

## Commands

```sh
cd infra/ansible
ansible-galaxy role install -r requirements.yml -p galaxy_roles
ansible-galaxy collection install -r requirements.yml -p collections
cp inventory/onprem.ini.example inventory/onprem.ini          # or cloud.ini.example, or let OpenTofu write it
ansible-playbook -i inventory/onprem.ini site.yml               # first install
ansible-playbook -i inventory/onprem.ini deploy.yml -e app_version=2026.10.1
ansible-playbook -i inventory/onprem.ini backup.yml -e fetch_backup=true
ansible-playbook -i inventory/onprem.ini restore.yml -e dump_file=/opt/smart-helpdesk/backups/helpdesk-20261001T023000Z-daily.dump \
  -e objects_file=/opt/smart-helpdesk/backups/objects-20261001T023000Z-daily.tar.gz
cp group_vars/all/vault.yml.example group_vars/all/vault.yml && ansible-vault encrypt group_vars/all/vault.yml   # only if shared secrets exist
ansible-playbook -i inventory/cloud.ini site.yml --ask-vault-pass                                              # when vault.yml exists
```

`just infra-check` runs the static checks (also the `infra` CI workflow): `ansible-playbook --syntax-check` of the four playbooks and `ansible-lint` 26.8 (production profile, through `uvx`, not installed), plus the OpenTofu checks.

### First deployment to a real VM

What the owner runs once a Debian 13 or Ubuntu 24.04 VM exists (any provider, or `tofu apply` from [terraform.md](terraform.md)):

1. DNS: A records for `shp`, `app.shp`, `api.shp`, `admin.shp`, `monitor.shp`, `docs.shp`, `files.shp`, `mail.shp` (or `*.shp` plus `shp`) → the VM address ([production.md §DNS](production.md#dns-for-shpsubhambhandaricomnp)). Ports 22, 80, 443 open at the provider.
2. SSH as a sudo user works: `ssh deploy@<ip>` (cloud-init creates `deploy`; on a hand-made VM set `ansible_user` to the provider's default user).
3. Images: CI's `build` workflow publishes `ghcr.io/<owner>/smart-helpdesk-{backend,proxy}` on push to `main` and on `v*` tags. Tag a release (`git tag v2026.10.1 && git push --tags`) or set `app_version=<git sha>`; if the packages are private, set `registry_username` and `vault_registry_password`. Without a registry: `docker save smart-helpdesk-backend:<tag> smart-helpdesk-proxy:<tag> | gzip > images.tar.gz` and `image_archive=…/images.tar.gz`.
4. `cp inventory/cloud.ini.example inventory/cloud.ini`, fill `ansible_host`, `platform_domain`, `platform_admin_email`, mail settings; then `ansible-playbook -i inventory/cloud.ini site.yml`.
5. `just prod-smoke shp.subhambhandari.com.np` (and `HEALTH_TOKEN=<from host_vars/<host>.secrets.yml>`); the platform admin signs in on `https://admin.shp…` with `platform_admin_password` from the secrets file; create workspaces on the host with `docker compose run --rm migrate php artisan platform:create-tenant acme "Acme Ltd" --owner=…` (the owner receives an invitation mail; the link is also printed).
6. Save `host_vars/<host>.secrets.yml` in the password manager.

## Idempotency and convergence

Secrets are generated only when absent; `.env` is templated; `docker_compose_v2` reconciles rather than recreates; migrations are Laravel-idempotent (`changed` only when a migration ran); first-run steps are marker-guarded; the bucket step applies only when `storage:ensure-bucket --check` reports a difference. Measured: the second `site.yml` run on the rehearsal host reported `changed=0`.

## Rehearsal (M3-14, 2026-09-21)

No cloud credentials or VM were available on the build machine, so the playbooks ran against a disposable "fresh Debian VM": a privileged `debian:trixie` container with systemd as PID 1 and volumes for `/var/lib/docker` and `/var/lib/containerd` (Docker 29 keeps images in the containerd store; nested overlay needs a real filesystem underneath), reached with `ansible_connection=community.docker.docker`, with `manage_firewall=false`, `harden_ssh=false`, `swap_size_mb=0`, `kernel_tuning=false` (ufw, swap and `vm.*` sysctls are not namespaced and would change the workstation) and the images from an `image_archive`.

| Run | Result |
|---|---|
| `site.yml`, single-tenant (`host_layout=single`, `tls_mode=internal`, `single_tenant=corp`) | first install in 2 min 18 s (Docker CE from download.docker.com included), `failed=0`; smoke through the local proxy passed |
| owner invitation accepted over the API, then `smoke.sh` with sign-in | all checks passed except `/v1/health` (see production.md §As built) |
| `site.yml` again | `changed=0` |
| `helpdesk-backup.service` started by hand; `systemctl list-timers` | dump + object archive written; next run 02:30 UTC |
| `backup.yml -e fetch_backup=true` | files on the controller |
| `deploy.yml` | green; Horizon restarted; smoke passed |
| one ticket created after the backup, then `restore.yml -e upload=true …` | ticket count back to the backup's 3, owner can sign in, smoke passed |
| `site.yml` with `host_layout=split`, `platform_domain=shp.corp.test` (multi-tenant) | converged; split-layout smoke with sign-in passed |

Bugs found and fixed by the rehearsal: playbook `group_vars/all` overriding the inventory (moved to role defaults); `docker_compose_v2_run` uses `cleanup`, not `rm`; `args: creates` is not supported by the Compose modules (marker files read with `stat` instead).
