# Host configuration (Ansible)

Terraform provisions, **Ansible configures**, Docker packages. The same playbooks configure a customer's on-prem server and the cloud VM; the inventory differs. ansible-core 2.21 with `community.docker` 5.3 (`docker_compose_v2`), `ansible.posix` 2.2, `community.general` 13.4 and the `geerlingguy.docker` role. Time budget: **≤ 1.5 days** in milestone 3.

## Layout

```text
infra/ansible/
├── ansible.cfg                 # inventory default, pipelining, retry files off
├── requirements.yml            # collections + geerlingguy.docker (pinned)
├── inventory/
│   ├── reference.ini           # generated by OpenTofu (gitignored)
│   └── onprem.ini.example      # customer copies and fills in
├── group_vars/
│   ├── all.yml                 # non-secret defaults (app_version, compose profiles, paths)
│   └── all/vault.yml           # ansible-vault: values that must live in git (none by default)
├── host_vars/                  # per-host generated secrets file (gitignored, created on first run)
├── site.yml                    # full install: common → docker → firewall → proxy → app → backup
├── deploy.yml                  # upgrade to app_version
├── backup.yml                  # ad-hoc backup now
├── restore.yml                 # restore from a dump + attachments prefix
└── roles/
    ├── common/
    ├── docker/
    ├── firewall/
    ├── proxy/
    ├── app/
    └── backup/
```

## Roles

| Role | Tasks | Lines (target) |
|---|---|---|
| `common` | apt update, `timezone` UTC, `unattended-upgrades`, `deploy` user with sudo, SSH hardening (key-only, no root), 2 GB swap file, `/etc/docker/daemon.json` with json-file rotation, `sysctl vm.overcommit_memory=1` for Valkey | ≤ 60 |
| `docker` | include `geerlingguy.docker` (`docker_install_compose_plugin: true`, `docker_users: [deploy]`); verify `docker compose version` ≥ 5 | ≤ 20 |
| `firewall` | `community.general.ufw`: default deny incoming, allow 22 (limited to `ssh_cidrs`), 80, 443 tcp, 443 udp; enable | ≤ 20 |
| `proxy` | render `infra/caddy/Caddyfile` from a template by `tls_mode` (`acme`, `internal`, `files`) and `host_layout` (`split`, `single`); copy customer certs to `/opt/smart-helpdesk/certs` when `tls_mode=files` | ≤ 40 |
| `app` | create `/opt/smart-helpdesk` tree; generate secrets once (see below); render `.env` (0600) from `templates/env.j2`; copy `compose.yaml`, `infra/compose/*`, `infra/postgres/init/*`; `docker login ghcr.io` (if private); `docker_compose_v2` `state: present, pull: always, wait: true` for `postgres`/`valkey` first, then `migrate` via `docker_compose_v2_run`, `key:generate` on first run, `tenants:create` when `single_tenant` is set, `db:seed --class=DefaultsSeeder`, then all services; wait for `/up` and `/health` | ≤ 120 |
| `backup` | `/usr/local/bin/helpdesk-pg-dump.sh`, systemd service + timer (daily 02:30), `/opt/smart-helpdesk/backups` retention 7 days, `restore.sh` | ≤ 40 |

### Secret generation (idempotent, per host)

```yaml
# roles/app/tasks/secrets.yml
- name: Load previously generated secrets
  ansible.builtin.include_vars: { file: "{{ inventory_dir }}/../host_vars/{{ inventory_hostname }}.secrets.yml" }
  failed_when: false

- name: Generate missing secrets
  ansible.builtin.set_fact:
    generated_secrets:
      db_superuser_password: "{{ db_superuser_password | default(lookup('community.general.random_string', length=32, special=false)) }}"
      db_owner_password: "{{ db_owner_password | default(lookup('community.general.random_string', length=32, special=false)) }}"
      db_app_password:   "{{ db_app_password   | default(lookup('community.general.random_string', length=32, special=false)) }}"
      db_backup_password: "{{ db_backup_password | default(lookup('community.general.random_string', length=32, special=false)) }}"
      redis_password:    "{{ redis_password    | default(lookup('community.general.random_string', length=32, special=false)) }}"
      health_token:      "{{ health_token      | default(lookup('community.general.random_string', length=40, special=false)) }}"
      s3_key:            "{{ s3_key            | default(lookup('community.general.random_string', length=20, special=false, upper=true, lower=false)) }}"
      s3_secret:         "{{ s3_secret         | default(lookup('community.general.random_string', length=40, special=false)) }}"
      backup_archive_password: "{{ backup_archive_password | default(lookup('community.general.random_string', length=32, special=false)) }}"

- name: Persist secrets next to the inventory (0600, gitignored)
  ansible.builtin.copy:
    dest: "{{ inventory_dir }}/../host_vars/{{ inventory_hostname }}.secrets.yml"
    content: "{{ generated_secrets | to_nice_yaml }}"
    mode: "0600"
  delegate_to: localhost

- name: Write Compose file secrets
  ansible.builtin.copy:
    dest: "/opt/smart-helpdesk/secrets/{{ item.key }}"
    content: "{{ item.value }}"
    owner: "33"          # www-data inside the backend image reads DB_PASSWORD_FILE; PostgreSQL reads them as root
    group: deploy
    mode: "0640"
  loop: "{{ generated_secrets | dict2items | selectattr('key', 'search', '^db_') | list }}"
  no_log: true
```

The files stay unreadable to other host users. PostgreSQL does not need them to be readable by its own user, because `infra/postgres/entrypoint.sh` reads them as root before the server starts ([docker.md](docker.md#postgresql-bootstrap)).

`APP_KEY` is generated inside the container on first run (`key:generate --show`) and written back into `.env` by the role. The persisted secrets file is the only copy outside the host; it belongs in the operator's password manager, not in git.

## Playbooks

```yaml
# site.yml
- hosts: helpdesk
  become: true
  roles: [common, docker, firewall, proxy, app, backup]
```

```yaml
# deploy.yml  (ansible-playbook deploy.yml -e app_version=2026.10.1)
- hosts: helpdesk
  become: true
  become_user: deploy
  tasks:
    - name: Pre-deploy database dump
      ansible.builtin.command: /usr/local/bin/helpdesk-pg-dump.sh pre-deploy
    - name: Update APP_VERSION in .env
      ansible.builtin.lineinfile: { path: /opt/smart-helpdesk/.env, regexp: '^APP_VERSION=', line: "APP_VERSION={{ app_version }}" }
    - name: Pull images
      community.docker.docker_compose_v2_pull: { project_src: /opt/smart-helpdesk }
    - name: Maintenance mode
      community.docker.docker_compose_v2_exec: { project_src: /opt/smart-helpdesk, service: app, command: php artisan down --retry=30 }
    - name: Migrate (owner role)
      community.docker.docker_compose_v2_run:
        project_src: /opt/smart-helpdesk
        service: app
        command: php artisan migrate --force
        env: { DB_USERNAME: helpdesk_owner, DB_PASSWORD_FILE: /run/secrets/db_owner_password }
        rm: true
    - name: Terminate Horizon so workers restart on new code
      community.docker.docker_compose_v2_exec: { project_src: /opt/smart-helpdesk, service: horizon, command: php artisan horizon:terminate }
      failed_when: false
    - name: Recreate services on the new image
      community.docker.docker_compose_v2: { project_src: /opt/smart-helpdesk, state: present, pull: never, remove_orphans: true, wait: true }
    - name: Leave maintenance mode and check health
      community.docker.docker_compose_v2_exec: { project_src: /opt/smart-helpdesk, service: app, command: "sh -c 'php artisan up && php artisan health:check --fail-command-on-failing-check'" }
```

`backup.yml` runs `backup:run` inside `app` plus the host dump; `restore.yml` takes `dump_file` and `attachments_prefix` variables ([disaster-recovery.md](disaster-recovery.md)).

## Idempotency and convergence

Every role is re-runnable: secrets are generated only when absent, `.env` is templated (changes trigger a `compose up` handler), `docker_compose_v2` reconciles rather than recreates, migrations are Laravel-idempotent, seeding runs only when a marker file `/opt/smart-helpdesk/.seeded` is absent. Running `site.yml` twice produces zero changes.

## Same playbooks, two targets

| Variable | On-prem | Cloud reference |
|---|---|---|
| inventory | hand-written from the example | generated by OpenTofu |
| `tls_mode` | `internal` or `files` | `acme` |
| `host_layout` | `single` | `split` (`platform_domain: shp.subhambhandari.com.np`) |
| `storage_profile` | true (or false with customer S3 vars) | false (Spaces vars from inventory) |
| `single_tenant` | set | unset |
| `ssh_cidrs` | office range | operator range |

## Commands

```sh
cd infra/ansible
ansible-galaxy install -r requirements.yml
ansible-playbook -i inventory/onprem.ini site.yml                     # first install (≈ 6 min on a 2 vCPU VM)
ansible-playbook -i inventory/onprem.ini deploy.yml -e app_version=2026.10.1
ansible-playbook -i inventory/onprem.ini backup.yml
ansible-playbook -i inventory/onprem.ini restore.yml -e dump_file=/opt/smart-helpdesk/backups/helpdesk-2026-10-01.sql.gz
ansible-vault edit group_vars/all/vault.yml                            # only if shared secrets exist
```

CI runs `ansible-lint` and `ansible-playbook --syntax-check` on every change under `infra/ansible/`.
